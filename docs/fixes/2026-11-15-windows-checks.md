## Found during the checks

1. **A missing parent folder in `MD_DESKTOP_DIR` crashes with a raw error trace.** With `MD_DESKTOP_DIR=C:\Temp\mdlink-test\MD-desktop` and no `C:\Temp\mdlink-test`, the script printed `Error: ENOENT: no such file or directory, mkdir 'C:\Temp\mdlink-test\MD-desktop.new'` and a stack trace (`tools/desktop-install.mjs:363`, `fs.mkdirSync(stage)` makes only the last folder). Nothing was changed. The default location under `%LOCALAPPDATA%` always exists, so the normal install is not affected. **Fixed** on Gianni's "1 A": e7a633e checks the parent before anything is touched and stops with a plain message; two unit tests (missing parent, parent is a file). An Opus check (high) confirmed nothing changes before the check fires and both tests fail without the fix; its one Low item (the wording for a disconnected drive and for a parent that is a file) is fixed in 2a0f721. After both: `npm run check` passes (170 passed, 4 skipped); the missing-parent retry and `Q:\` (no such drive) print the plain message; a normal install to `C:\Temp\Café\MD-desktop` still works.
2. **A side effect worth knowing, not a bug.** Setting `[Console]::OutputEncoding` in one PowerShell call also switches the console that Node shares with later child processes, so later calls in the same Node process get UTF-8 even without the switch. The script sets it on every call, so this does not matter for it; it only fooled a first comparison here.
3. **Keystrokes during the live checks.** The Playwright windows take focus; text typed on the PC while they run lands in the test window (seen: a stray "it is h" in a test tab's draft at 21:50). It reached only the test copy of the session, not real files.
